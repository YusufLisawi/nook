# Clips — clipboard, screenshots and recordings history

Implemented on `agent/clips`, continuing the partial work already present in this worktree.

## What shipped

- Native clipboard polling for text, rich text flattened to plain text, links, PNG/TIFF images, file URLs and colors. Password-manager concealed/transient/autogenerated markers are checked across every pasteboard item before reading content. Ignored application names/bundle IDs default to 1Password, Bitwarden and Keychain Access. The service respects `LinkCatcher.ignoreClipboardUntil`; LinkCatcher itself is unchanged.
- Local history with deduplication, pins, age/capacity pruning, private image files and background persistence in `~/Library/Application Support/Nook/Clips/`. Defaults: enabled, 30 days, 500 unpinned items. Pinning survives restart and exempts entries from pruning. Nook-owned image cleanup uses Trash.
- Screenshot/recording indexing in the macOS screenshot location (`com.apple.screencapture` preferences, default Desktop), with a settings override, initial scan, directory watcher, settle delay and periodic recovery scan. Capture names and Spotlight metadata identify files. Quick Look generates lazy thumbnails; Vision recognizes screenshot text locally in a serial background queue and caches results until the file changes.
- `nook.clips` bridge: history/screenshots with bare terms plus `name:`, `text:` and local `date:` filters; native image copy; paste after closing the notches and verifying the target app still has focus; open, reveal, Trash, pin/unpin, clear, Quick Look, thumbnail and status. API and deletion semantics are documented in `PLUGINS.md`.
- Bundled `Plugins/clips`, order 44, height 360. Clipboard list and screenshot/recording grid use the injected UI kit. Arrow navigation, Tab, Enter copy, Command-Enter paste, Command-K actions, Space Quick Look and Escape are supported. Deletion requires inline confirmation. Loading/empty/error states and stale-response protection are included. The listbox keeps keyboard focus across updates and exposes its selected option to accessibility APIs.
- Native grouped Settings → Clipboard: capture toggle, retention, capacity, ignored apps, capture-folder override, OCR toggle, item count and confirmed clear.

## Lead's manual test

Use only one Nook instance when reviewing this build: quit the existing app before opening the review build. These interactive checks were deliberately left to the lead under the task's no-launch/no-GUI restriction.

1. Open Settings → Clipboard. Confirm native grouped controls and live updates. Use a disposable screenshot folder override for testing; check that an invalid folder produces a useful error and that restoring the path recovers.
2. Copy text, formatted text, a URL, an image, a color and disposable Finder files. Confirm previews/types, recopy deduplication, pins at the top, and persistence after restart. Copy from an ignored app and verify it is absent; pause capture and confirm future copies are not added.
3. Put real screenshots and screen recordings in the capture folder. Check thumbnails and date captions. Search an obvious word visible only inside a screenshot with `text:`, and combine `name:"Screen Shot" date:today`. Check `date:yesterday` and an explicit `YYYY-MM-DD`. Disable OCR to stop new recognition; existing cached text remains searchable.
4. Navigate both views with arrows and Tab. Enter copies; Command-K opens actions; Escape dismisses actions/confirmation first, then closes the notch. Space opens Quick Look for file-backed entries. Verify VoiceOver announces selection as it changes.
5. In a disposable text document, manually invoke Command-Enter from Clips. With Accessibility allowed, confirm the notch closes and the previous app receives the paste. With permission denied, confirm the inline error and that ordinary Copy remains available. Check native Quick Look, Finder reveal and opening files/links.
6. Trash only disposable test files. The confirmation explicitly says that file-reference entries affect original files. Check that clear includes pins, preserves screenshot originals and referenced files, and moves Nook's saved clipboard image copies to Trash.

## Limits and risks

- Capture polls every 750 ms; rapid changes can be missed. The pre-launch clipboard is intentionally skipped. App attribution/ignore matching uses the frontmost app at capture time. Text above 1 MiB and image representations above 32 MiB / 40 megapixels are skipped.
- Screenshot indexing is immediate-folder only, with the newest 2,000 unpinned captures plus pins. Names cover common English/French/German/Spanish forms; other renamed/localized files depend on Spotlight's screen-capture attribute. Folder access may require Files & Folders permission. A 30-second rescan recovers missed/incomplete writes. These limits never remove originals.
- Recording thumbnails and filename/date search are supported; video-frame OCR is not. OCR is local and cached, including empty/unreadable results until modification. Disabling OCR does not erase existing cached text.
- History and OCR caches use user-only permissions and are not separately encrypted. Explicit Delete trashes associated original files; retention/clear affect only history and Nook-owned images. Failed Trash operations are reported.
- Live panel layout, target-app paste behavior/permission prompts, and the interactive Quick Look panel require the manual checks above. Automated tests did not issue paste events or open native UI.
